22 ## How to integrate libraries {#section-id}
23 
24 With the help of the .tiares file, libraries can be easily integrated in the Module Builder. To do this, the file must first be opened in Visual Studio.
25 
26 ![Open Tiares](../MAC_use_cases/Images/OpenTiares.png)
27 
28 In the newly opened window, the selection menu can now be opened using the button in the top left-hand corner.
29 The desired library must then be selected there.
30 
31 ![Open Library](../MAC_use_cases/Images/OpenLibrary.png)
32 
33 By clicking on the "Mastercopies" area and then pressing the "Add" button, everything is included. This window can then be closed again, as everything is saved automatically.
34 
35 ![Add Library](../MAC_use_cases/Images/AddLibrary.png)
36 
37 To integrate parts of the library use the code explainned in [Use Integrated Libraries](class_m_a_c__use__cases_1_1_model_1_1_use_cases_1_1_integrate_libraries.html)

39 ## How to use different lanugages {#localization-id}
40 
41 Currently the Modular Application Creator supports following languages:
42 
43 - en - English
44 - de - German
45 - zh - Chinese
46 
47 The language can be changed during runtime in the settings menu. Depending on the selected language one of the defined XAML ResourceDictionary will be used.
48 
49 ![XAML ResourceDictionary](../MAC_use_cases/Images/LocalizationXamlResourceDictionary.png)
50 
51 Create KeyValue pairs in the ResourceDictionaries with matching Key and use them with DynamicResource Binding in your XAML files:
52 
53 ```xaml
54  <TextBlock Text="{DynamicResource SampleText}" />
55 ```

57 ## How to upgrade a v20 module to v21 {#module-upgrade-id}
58 
59 There have been major changes in the new TIA Portal V21 Openness API. This API **is not backward compatible** with any previous APIs, therefore every Openness user **must upgrade** their project to the latest API. To do this task with Siemens Modular Application Creator Equipment Modules, this manual will make it easier.
60 
61 There are two easy ways to do it, if you already have the **Siemens Collaboration Framework** installed in your project, or if you don’t have it installed yet but agree to install it. This framework comes with MAC-MB by default and can only be missing in case of (un)intended removal, or in a case of a very old EQM project.
62 
63 The third, bit harder way to do it is to direct reference the new dll-s into the csproj.
64 
65 ### How does it work if the EQM is not upgraded?
66 
67 If you install the module to MAC V21 and generate, this is the result:
68 
69 ![Generation Error](../MAC_use_cases/Images/V20_To_V21_GenerationError.png)
70 
71 The v20 Siemens.Engineering.dll is not compatible with v21 dll-s, and also it does not exist in v21 installs, so MAC throws an assemby load exception. (This is expected behavior in this case).
72 
73 #### **Fix 1** - If you already have collaboration framework installed on your project.
74 
75 If your project has collaboration framework then the changeover can be very easy.
76 
77 1. Install the latest v21 MAC-MB
78 2. In your EQM project, select „Manage NuGet Packages”
79 3. Select the package source: „MacMbPackages”
80 
81  ![Select MacMb Package Source](../MAC_use_cases/Images/V20_To_V21_SelectMacMbPackages.png)
82 4. Update all of these packages to the latest.
83 
84  <span style="color:red">**If you have “EquipmentModule.Build.Tasks” package, the update will not be an option because of the rename of this package. Please uninstall it and install “Siemens.EquipmentModule.Build.Tasks” latest version from this repo.**</span>
85 
86  ![Update MAC Packages](../MAC_use_cases/Images/V20_To_V21_UpdateMacPackages.png)
87 5. Rebuild your project
88 6. If the build fails, please proceed to fix incompatibilities with the Openness V21 API until every error is resolved.
89 Some useful links:
90 https://asrdwiki.siemens.com/tiapdev/index.php/Openness/How_to_handle_cross_dependencies_of_EOM_with_Segmented_Engineering_Assemblies
91 https://asrdwiki.siemens.com/tiapdev/index.php/Openness/How_to_Generate_Openness_Segmented_Assemblies
92 https://asrdwiki.siemens.com/tiapdev/index.php/Openness/How_to_Use_Openness_Segmented_Assemblies_in_Tests
93 7. Try to generate your module with MAC V21. It should work now.
94 
95  ![Generation Success](../MAC_use_cases/Images/V20_To_V21_GenerationSuccess.png)
96 8. If the generation fails, please go back to point #6.
97 9. (Optional) There might be an old API dll stored in your EQM project. You can either change this dll to the V21 engineering dll-s, or you can delete it if your project does not use it. It does not matter at runtime.
98 
99  ![MAC Old Engineering DLL](../MAC_use_cases/Images/V20_To_V21_OldEngineeringDll.png)
100 
101 #### **Fix 2** - If you do not have the Collaboration Framework installed on your project
102 
103 If you do not have a nuget package reference for the Collaboration Framework, your module might use a direct dll reference to Siemens.Engineering.dll. The easiest way to fix this is to remove the dll reference and install the Collaboration Framework.
104 1. Remove all references for Siemens.Engineering.dll from your project.
105 2. Install the latest v21 MAC-MB
106 3. In your EQM project, select „Manage NuGet Packages”
107 4. Select the package source: „MacMbPackages”
108 
109  ![Select MacMb Package Source](../MAC_use_cases/Images/V20_To_V21_SelectMacMbPackages.png)
110 5. On the “Browse” tab, find and install “Siemens.Collaboration.Net.TiaPortal.Openness.Startdrive.Extensions”. The other packages will be installed as dependencies automatically.
111 
112  ![Install StartDrive Extensions](../MAC_use_cases/Images/V20_To_V21_InstallStartDriveExtensions.png)
113 6. Please Follow **Fix 1** from point **#4** – Update the NuGet packages.
114 
115 #### **Fix 3** - If your project has direct dll references and is not planned to change it for the Collaboration framework
116 
117 1. Locate your TIA Portal install path, and find the API dll-s.
118 (Usually: C:\Program Files\Siemens\Automation\Portal 21\PublicAPI\V21\net48).
119 2. Select the non “AddIn” – dll-s.
120 
121  ![Required TIA V21 DLLs](../MAC_use_cases/Images/V20_To_V21_RequiredNewEngineeringDlls.png)
122 3. Add these dll-s into your project so the references will not be computer specific.
123 
124  ![New Engineering DLLs](../MAC_use_cases/Images/V20_To_V21_NewEngineeringDlls.png)
125 4. Make a dll reference for all 9 of them.
126 
127  ![New Engineering DLL References](../MAC_use_cases/Images/V20_To_V21_NewEngineeringReferences.png)
128 5. Please Follow **Fix 1** from point **#4** – Update the NuGet packages. **At this point you will not have to update the Collaboration package as your project does not have it.**
